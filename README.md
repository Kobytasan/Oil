# 🛒 Веб-ресурс електронної комерції оптово-роздрібного підприємства «Оліс»

> **Дипломна робота:** Тестування веб-ресурсу електронної комерції оптово-роздрібного підприємства «Оліс»

Інтернет-магазин оптово-роздрібного підприємства: каталог товарів, кошик,
оформлення замовлень з автоматичними оптовими цінами та панель керування
для працівників підприємства.

## 📄 Сторінки сайту

- `/` — головна (категорії, хіти продажів)
- `/catalog` — каталог з фільтром за категоріями та пошуком
- `/product/:id` — сторінка товару (роздрібна та оптова ціни)
- `/cart` — кошик (автоматична оптова ціна від 10 шт. позиції)
- `/checkout` — оформлення замовлення
- `/order/:id` — статус замовлення за номером
- `/login` — вхід працівників → `/admin` — панель керування

## 🧪 Автоматичні тести (у комплекті)

У проєкті є готовий набір автотестів — 22 перевірки (кошик, оптові ціни,
замовлення, вхід, права доступу, CRUD товарів):

```bash
# тест без бази даних (in-memory PostgreSQL)
npm install pg-mem --no-save
node test-local.js   # у першому терміналі — запускає сервер на порту 3001
node test-flow.js    # у другому терміналі — прогоняє всі тест-кейси
```

Кожен рядок `PASS | ...` — це виконаний тест-кейс. Результат можна
вкласти в розділ дипломної роботи «Тестування».

## 🧪 Що перевірити під час тестування

1. Каталог: фільтр категорій, пошук за назвою, сторінка товару.
2. Кошик: додавання, зміна кількості, видалення; при 10+ шт. однієї
   позиції ціна автоматично змінюється на оптову (перевірте сторінку
   кошика та сторінку товару).
3. Оформлення замовлення → номер замовлення → сторінка `/order/:id`.
4. Вхід директора (`director` / `Director2026!`):
   - Огляд: статистика продажів;
   - Товари: додати / відредагувати / видалити позицію;
   - Замовлення: змінити статус (нове → підтверджено → виконано);
   - Працівники: додати новий обліковий запис, видалити.
5. Спробувати зайти під касиром (`kasa`) — розділ «Товари» буде прихований
   (перевірка розмежування прав).

## 🚀 Локальний запуск

```bash
npm install
# створіть файл .env за зразком .env.example та вставте DATABASE_URL з Neon
npm start
# відкрийте http://localhost:3000
```

## ☁️ Деплой на Render + Neon

### 1. База даних Neon
1. Зареєструйтесь на [neon.tech](https://neon.tech) → **Create project**.
2. Скопіюйте **Connection string** (вида `postgresql://...neon.tech/neondb?sslmode=require`).

### 2. Сайт на Render
1. Завантажте цю папку в репозиторій GitHub.
2. Render → **New → Web Service** → підключіть репозиторій.
3. Налаштування:
   - **Environment:** Node
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
4. У розділі **Environment Variables** додайте:
   - `DATABASE_URL` = рядок підключення з Neon
   - `SESSION_SECRET` = будь-який довгий рядок
5. Натисніть **Deploy**. При першому запуску таблиці створяться й
   наповняться тестовими даними автоматично.

## 🛠 Технології

- Node.js + Express (SSR, шаблонізатор EJS)
- PostgreSQL (Neon), драйвер `pg`
- Сесії: `express-session`, паролі: `bcryptjs`
- Без фреймворків на клієнті: чисті HTML/CSS/JS
